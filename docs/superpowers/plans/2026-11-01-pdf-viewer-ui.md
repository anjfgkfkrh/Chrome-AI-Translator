# PDF 뷰어 화면 개선 인수인계

**목표:** 지금의 최소 뷰어를 크롬 내장 PDF 뷰어처럼 보이고 쓰이게 만든다. PDF 번역 동작은 바꾸지 않는다.

**시작 지점:** 브랜치 `pdf-translation`. 시안 패치 `docs/superpowers/plans/2026-11-01-pdf-viewer-ui.patch`가 화면의 대부분을 담고 있다.

**배경 문서:** `docs/superpowers/specs/2026-11-01-pdf-translation-design.md`, `SPEC.md` 13장의 "PDF" 항목. 필요한 부분만 읽는다.

## 가장 중요한 규칙: 큰 결정을 하지 않는다

구현자(Sonnet)는 이 문서에 적힌 일만 한다. 사용자의 지시다.

### 구현자가 정해도 되는 것

- 변수와 함수의 이름, 파일 안의 코드 배치
- 이 문서가 정한 동작을 시험하는 테스트의 세부 작성
- 타입 오류, 오타처럼 동작이 바뀌지 않는 수정

### 멈춰야 하는 경우

아래 중 하나라도 해당하면 **더 진행하지 말고** 다음 절차를 따른다.

- 이 문서에 없는 동작, 화면, 문구, 수치를 정해야 한다.
- 지시를 해석하는 방법이 둘 이상이다.
- 무엇이 맞는지 모르겠다.
- 같은 문제를 두 번 고쳐도 실패한다.
- 테스트를 통과시키려면 기대값을 낮추거나 테스트를 건너뛰어야 한다.
- 계획된 방법이 동작하지 않아 다른 방법이 필요하다.
- 새 의존성, 새 권한, 범위 밖 파일 변경이 필요하다.

### 멈춘 뒤의 절차

1. 코드 작업을 멈춘다. 임시 방편으로 우회하지 않는다.
2. `Agent` 도구를 `model: "opus"`, `subagent_type: "Plan"`으로 호출해 조력을 받는다. 사용자가 이 호출을 허락했다. 프롬프트에는 상황, 시도한 일, 오류 원문, 관련 파일 경로를 넣고 다음을 요청한다.
   - 결정이 필요한 항목을 정리한다.
   - 항목마다 선택지와 장단점, 추천안을 적는다.
   - 파일을 수정하지 않는다. 사용자 대신 결정하지 않는다.
3. 결과를 `SPEC.md` 12.1절의 보고 형식으로 사용자에게 보고한다. 같은 시점의 결정은 한 보고에 묶는다.
4. 사용자의 답을 기다린다. 추천안이 있어도 답을 받기 전에는 적용하지 않는다.
5. 답을 받으면 `SPEC.md` 13장에 기록하고 이어서 진행한다.

Opus는 조언만 한다. 최종 결정은 사용자만 한다.

## 작업 규칙

- 커밋은 `pdf-translation` 브랜치에 작업 단위로 한다. **push하지 않는다.** 다른 브랜치에 합치지 않는다.
- 작성자: `git -c user.name="dlawhdgur01" -c user.email="dlawhdgur01@gmail.com" commit`
- 커밋 메시지는 저장소처럼 한국어 한 줄이고, 끝의 저작 표시 줄은 실행 세션의 안내를 따른다.
- API 키 파일을 읽거나 출력하지 않는다. 실제 API 호출이 필요 없다.
- `manifest.json`의 권한과 `src/content/`, `src/background/`, `src/popup/`, `src/options/`를 바꾸지 않는다. 바꿔야 하면 멈춘다.
- 코드 주석과 이름은 주변 코드를 따른다.

## 범위

- 포함: 파일명, 쪽 번호 입력, 축소·배율 입력·확대, 페이지 맞춤, 회전, 두 쪽 보기, 다운로드, 인쇄, 번역/원문, 왼쪽 썸네일 패널
- 제외: 펜, 주석, 서명, 저장 시 편집, 프레젠테이션 모드, 뷰어 검색 UI, 번역문이 포함된 PDF 내보내기

## 시안이 이미 담은 것

패치는 `src/pdf/viewer.html`, `viewer.css`, `viewer.ts`, `overlay.ts`를 바꾼다.

- 56px 어두운 도구 막대(`#323639`), 본문 배경 `rgb(40, 40, 40)`, 페이지 그림자, 썸네일 패널(폭 200px, 처음에는 닫힘)
- `#page-input`, `#page-total`, `#zoom-input`, `#fit`, `#rotate`, `#menu`, `#title`, 그리고 `#download`, `#print` 버튼 모양
- 기본 배율 `"auto"`, 회전 시 번역층이 함께 도는 처리 (`PageLookup.pagesRotation`, `rotatedPoint`)

시험에서 확인한 것은 기본 화면, 썸네일 패널 열기, 90도 회전이다. 쪽 번호 입력, 배율 입력, 맞춤 버튼은 코드만 있고 시험하지 않았다. 도구 막대 색 `#323639`는 크롬 소스에서 확인하지 못한 값이며 그대로 둔다.

## 작업 2: 다운로드와 인쇄

`src/pdf/viewer.ts`에서 열린 문서를 변수로 보관한다.

- [ ] `#download`: `await pdf.getData()`로 받은 원본 바이트로 `application/pdf` Blob을 만들고 `<a download>`로 저장한다. 파일명은 `document.title`이고 `.pdf`로 끝나지 않으면 붙인다. 만든 URL은 해제한다.
- [ ] `#print`: 같은 Blob의 URL을 숨긴 `<iframe>`에 넣고, 불러온 뒤 `iframe.contentWindow.print()`를 부른다.
- [ ] 문서가 열리기 전에는 두 버튼이 아무 일도 하지 않는다.
- [ ] E2E: 다운로드 버튼으로 받은 파일의 바이트가 원본과 같고 파일명이 맞는다.
- [ ] 인쇄가 headless에서 자동 확인되지 않으면 버튼 동작 시험은 넣지 않고 수동 확인으로 남긴다. **이 방법이 실제로 동작하지 않는 것이 드러나면 다른 방법을 찾지 말고 멈춘다.**
- [ ] 커밋: `PDF 다운로드와 인쇄`

## 작업 3: 두 쪽 보기

`SpreadMode`는 `pdfjs-dist/web/pdf_viewer.mjs`에서 내보내는지 확인하고 쓴다. 내보내지 않으면 값 `0`(NONE), `1`(ODD)을 이름 있는 상수로 둔다.

- [ ] `#fit` 다음에 `#two-page` 아이콘 버튼을 더한다. `aria-label`은 `두 쪽 보기`다. 켜지면 `data-active`를 달고 색은 `#fit`과 같게 한다.
- [ ] 누르면 `viewer.spreadMode`를 NONE과 ODD 사이에서 바꾸고 번역층 위치를 다시 맞춘다.
- [ ] 아이콘은 두 개의 세로 사각형으로 된 단순한 SVG를 직접 그린다.
- [ ] E2E: 켜면 1쪽과 2쪽의 `.page`가 같은 높이에 나란히 있고, 두 쪽의 `.pdf-layer`가 각 `.page`의 안쪽과 1px 이내로 맞으며, 끄면 세로로 돌아간다.
- [ ] 위치가 맞지 않으면 두 번까지 고쳐 보고, 그래도 안 되면 멈춘다.
- [ ] 커밋: `PDF 두 쪽 보기`

## 작업 4: 도구 막대 시험

- [ ] E2E: `#page-input`에 `4`를 넣고 Enter를 누르면 4쪽으로 이동한다. 범위 밖 값은 현재 쪽 번호로 되돌아간다.
- [ ] E2E: `#zoom-input`에 `150`을 넣고 Enter를 누르면 `150%`로 표시된다. 25 미만이나 500 초과는 이전 값으로 돌아간다.
- [ ] E2E: `#fit`을 누르면 `data-active`가 켜지고 다시 누르면 꺼진다.
- [ ] E2E: `#menu`로 패널이 열리고, 썸네일을 누르면 그 쪽으로 이동하며, 현재 쪽의 썸네일에 `data-active`가 있다.
- [ ] E2E: `#rotate`를 누른 뒤 번역층 영역이 `.page`의 안쪽 영역과 1px 이내로 맞는다.
- [ ] 시험에서 버그가 나오면 원인이 뚜렷한 경우에만 고친다. 동작을 새로 정해야 하면 멈춘다.
